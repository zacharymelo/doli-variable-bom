# Ready-made patched copies of `htdocs/mrp/class/mo.class.php`

For installs where running `apply_hook.php` is not an option. Each folder holds the complete file of **one exact
Dolibarr release** with the `processBOMLines` hook (version 2) already added. Nothing else differs from the release.

| Your Dolibarr version | File to use |
|---|---|
| 24.0.0 | `24.0.0/htdocs/mrp/class/mo.class.php` |
| 24.0.1 | `24.0.1/htdocs/mrp/class/mo.class.php` |
| 24.0.2 | `24.0.2/htdocs/mrp/class/mo.class.php` |

Where the file goes in your install: `htdocs/mrp/class/mo.class.php` (the folder structure here mirrors it).

## Steps

1. Check your version: Home > Setup > Other setup > About Dolibarr, or the version number at the bottom of any page.
   The release number must match exactly (24.0.1 is not 24.0.0): every release ships a different copy of this file.
2. On the server, rename `htdocs/mrp/class/mo.class.php` to `mo.class.php.orig`. This is your backup.
3. Copy the file of your version from this folder to `htdocs/mrp/class/mo.class.php`.
4. In Dolibarr, open the setup page of the Variable BOM module: "Hook processBOMLines of Dolibarr core" must say **Available**.

To go back, rename `mo.class.php.orig` to `mo.class.php`. The module then refuses manufacturing orders of variable BOMs
and leaves everything else alone.

After a Dolibarr upgrade the file is replaced by the new release's copy: redo the steps with the file of the new version.
If your version is not listed, do not use another version's file. Run `apply_hook.php` instead (it checks the code before
changing it), or ask for the file of your version to be generated (`dev/build_full_files.sh` in this repository).

Only the 24.0.0 copy has been run through the module's end-to-end tests; the 24.0.1 and 24.0.2 copies were generated by the
same script and syntax-checked.
